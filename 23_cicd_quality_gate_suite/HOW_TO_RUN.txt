AI EVALUATION CI/CD QUALITY GATE
================================

This module runs the automated evaluation suites from:

22_evaluation_automation_suite

It generates machine-readable reports and applies a final release decision.

Release decisions:

- PASS  -> exit code 0
- BLOCK -> exit code 1
- Configuration error -> exit code 2


1. PREREQUISITES
----------------

Recommended:

- Python 3.12
- Git
- GitHub repository
- GitHub Actions enabled

Check Python:

python --version

Check the active Python environment:

which python


2. GO TO THE REPOSITORY ROOT
----------------------------

cd /Users/prakashganji/Desktop/ai-qa-deepeval-metrics-series

Confirm:

pwd

----------------------------------

source .venv/bin/activate

Confirm:

4. INSTALL DEPENDENCIES
-----------------------

  -r 23_cicd_quality_gate_suite/requirements.txt

5. VALIDATE THE QUALITY-GATE FILES
----------------------------------

Validate the JSON configuration:

  23_cicd_quality_gate_suite/quality_gate_config.json \
  > /dev/null

Compile the Python files:

python -m py_compile \
  23_cicd_quality_gate_suite/generate_ci_summary.py \

6. TEST THE QUALITY-GATE LOGIC
------------------------------

Run:

python -m pytest \
  23_cicd_quality_gate_suite/test_ci_quality_gate.py \
  -v

Expected result:

8 passed

These tests validate the gate itself.

They confirm that:

- A complete passing report is accepted.
- A partial pass is blocked.
- A missing report is blocked.
- A pytest error is blocked.
- A zero-test report is blocked.
- Every release stage requires a 100% pass rate.

  23_cicd_quality_gate_suite/reports/critical_results.json.backup \

15. GITHUB ACTIONS WORKFLOW
---------------------------

The workflow is stored at:

.github/workflows/ai-evaluation-quality-gate.yml

It runs when:

- A pull request changes Module 22.
- A pull request changes Module 23.
- The workflow file changes.
- A change is pushed to main.
- The workflow is started manually.


16. PUSH THE WORKFLOW TO GITHUB
-------------------------------

Create a feature branch:

Check the staged files:

git diff --cached --name-only
git diff --cached --check

Commit:

git commit -m "Add AI evaluation CI quality gate"

Push:

git push -u origin feature/ai-evaluation-quality-gate

OPENAI_API_KEY is not required.

Future LLM-judge evaluations should use:

GitHub repository
-> Settings
-> Secrets and variables
-> Actions
-> New repository secret


22. BRANCH PROTECTION
---------------------

After the workflow has completed successfully at least once, the workflow can
be configured as a required status check.

GitHub repository
-> Settings
-> Branches or Rules
-> Add branch protection rule or ruleset
-> Target branch: main
-> Require status checks before merging
-> Select: AI Evaluation Release Gate

After this is enabled, a failed AI evaluation gate prevents the pull request
from being merged.


23. EXPECTED FINAL BEHAVIOUR
----------------------------

Passing evaluation:

Tests -> Reports -> Summary -> PASS -> Exit code 0 -> Merge allowed

Failed critical evaluation:

Tests -> Reports -> Summary -> BLOCK -> Exit code 1 -> Merge blocked

Missing evaluation evidence:

Missing report -> BLOCK -> Exit code 1 -> Merge blocked
